### 埋点：M3 完成率的硬前提

M3 = 提交数 ÷ 开始数，因此问卷工具必须支持**两处计数**：

1. **打开问卷即开始计数** —— 不是点「提交」时
2. **交卷计数** —— 点击提交时

导出必须包含 `submitted_at`（空 = 只开始未交卷）与 `survey_started`
（打开问卷即建行并置 `true`）。

> ⚠️ **若问卷工具无法在「打开」时落行，M3 就无法计算。** Google Forms 默认在提交时
> 才产生一行响应——用它投放前，必须确认其「响应目标 = 一次会话」或改用支持开始埋点的工具。
> 这条在任务 15 [A1.2] 的 schema 里已写死：`survey_responses.csv` 的 `survey_started` 列
> 记录「开始」，`submitted_at` 记录「提交」。

## 导出字段与 schema 对照

问卷工具的导出列名必须改为下表左列，否则 `compute_metrics.py` 会报「缺少必需列」。

| 导出列名 | 取值 | 供计算 |
|---|---|---|
| `respondent_id` | 邮箱哈希或问卷平台生成的唯一 ID | 去重 |
| `submitted_at` | ISO 8601；空 = 未提交 | **M3 分子** |
| `source_channel` | 投放渠道（对应任务 3 的分发记录） | 渠道归因 |
| `m4_answer` | `very_needed` / `somewhat_needed` / `not_needed` / `not_at_all` | **M4** |
| `m12_answer` | `strongly_agree` / `agree` / `neutral` / `disagree` / `strongly_disagree` | **M12** |
| `differentiation_needs` | `;` 分隔的勾选项（不含「其他」自由文本） | **M11** |
| `survey_started` | `true` / `false`；打开问卷即建行并置 `true` | **M3 分母** |

非指标题项（Q1–Q3、Q5–Q7、Q11–Q12）的答案**建议一并导出**，供任务 8 [H4.1] 做人群细分，
但不必写入 `survey_responses.csv`——该 schema 只承载指标字段。

## 反垃圾设计建议

任务 3 [H1.3] 投放时执行：

1. **单邮箱限一次**——问卷平台开启「限制为 1 次响应」
2. **异常作答识别规则**（人工抽查，不必全自动）：
   - 全选「非常同意」且 Q7 只勾了最后一项「上述都不是我的问题」→ 疑似敷衍
   - 完成时长 < 40 秒 → 疑似机器
   - Q2 选「还没用过」却回答了 Q4–Q12 的求职细节 → 自相矛盾
3. **已识别为敷衍的作答不写入 `survey_responses.csv`**——否则污染 M3 的分子与分母
4. 题目数量已控制在 14 题；**不要再加题**，题目越多完成率越低，M3 越难达标
