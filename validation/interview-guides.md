# 访谈执行手册 —— H1.1（开发者）与 H2.1（企业）

> **这是 H 轨（人工）任务的执行物料。** 访谈、发问卷、约时间全部由创始人执行，
> agent 不得代为完成，也不得代为勾选 `tasks.md`。
> 本文件的作用是：**让采集到的数据直接可聚合**，不必事后返工。

## 为什么这份提纲写得很死

`validation-metrics.md`「统计口径约定」要求：所有百分比指标必须能从结构化数据
**直接聚合得出**，不得依赖分析师手工估算。这意味着两件事：

1. **提纲里问的每一句话都要对应一个字段**——否则回答无法归类，该份访谈白做。
2. **痛点的措辞必须与问卷 Q7 完全一致**——否则 `interviews.csv` 的 `pain_points`
   与 `survey_responses.csv` 的 Q7 跨源聚合失效，M5 的两个口径会对不上。

> **S1/S2 达标前不要停。** 通过值：S1 ≥ 10 份开发者访谈、S2 ≥ 5 家企业访谈；
> 理想值 15 / 8。样本量不足会削弱统计效力，但**不构成假设证伪**——
> 判定阶梯规定 S1/S2/S3 未达标时用已完成样本重算 M4–M12，不直接判失败。

# 第一部分：开发者深度访谈（H1.1）

**目标**：10 份（理想 15）。**时长**：30–45 分钟。**形式**：语音/视频，转写留档。

## 触达渠道（`interviews.csv` 的 `channel` 字段取值）

| 取值 | 渠道 | 说明 |
|---|---|---|
| `github` | GitHub 开源项目作者 | 优先 LangChain / AutoGen / CrewAI 的 contributor、issue 里表达求职意向的人 |
| `huggingface` | Hugging Face 社区 | 讨论区、Space 作者 |
| `reddit` | Reddit r/LocalLLaMA 等 | r/LocalLLaMA、r/AI_Agents、r/ LangChain |
| `x` | X / Twitter | AI 圈，转推或个人简介含 Agent 项目 |
| `discord` | Discord 中文 AI 服务器 | LangChain / AutoGen 中文用户群 |
| `wechat` | 微信 / 中文 AI 社群 | 公众号、微信群 |
| `other` | 其他 | 其他渠道 |

> **不花钱购买名单，不强行推销。**重点是倾听。触达话术见文末。

## 开场白（照读）

> 「你好，我在做一个关于 AI Agent 开发者求职的研究，想了解你找工作时的真实情况。
> 大概 30 分钟，没有对错，不推销任何东西，也不录音用于招聘。
> 结果只会汇总成统计结论，不会公开到个人。可以吗？」

## 提问提纲

**每题都要落到 `interviews.csv` 的一个字段上。括号里是该字段。**

### 第 1 组：背景（2 分钟）

1. 「你现在做的是什么工作？在公司里的角色是什么？」 → `skill_tags`（结合下一问）
2. 「过去 12 个月你用过哪些 Agent 相关技术？」 → `skill_tags`（`;` 分隔，如 `LangChain;AutoGen;Python`）
3. 「你目前的求职状态是？」 → `job_search_status`
   - 建议取值：`actively_looking`（正在积极投递）/ `passive`（偶尔看看机会）/ `employed`（暂不换工作但会关注）/ `not_looking`（暂不求职）
4. 「你通常在哪里找这类岗位？过去 6 个月实际投了多少个？」 → 补充信息，**不入表**，用于判断痛点是否已解决

### 第 2 组：痛点（8 分钟）—— **最关键的一组**

> **逐条念下面 8 条，问「这条符合你的情况吗？」并记录勾选。**
> **措辞必须与问卷 Q7 一字不差**，这样 `pain_points` 与问卷才能跨源聚合。

| # | 痛点（念给受访者的话） | 记录代码 |
|---|---|---|
| 1 | 找不到纯 Agent 岗位，混在通用 AI/ML 岗位里 | `pp_agent_only` |
| 2 | 招聘方看不懂我的 Agent 项目经验 | `pp_unreadable_exp` |
| 3 | 每次面试都要从零解释什么是 Agent、多智能体怎么协作 | `pp_repeat_explain` |
| 4 | 岗位描述的技术栈与实际工作内容对不上 | `pp_stack_mismatch` |
| 5 | 薪资水平不透明，只能靠问 | `pp_salary_opaque` |
| 6 | 远程 Agent 岗位太少 | `pp_few_remote` |
| 7 | 缺少能展示 Agent 项目的公开作品集渠道 | `pp_no_portfolio` |

**记录规则**：
- 勾中的条目 → 写进 `pain_points`，用 `;` 分隔，**只写勾中的代码**
- 一条都没勾 → 追问一句「那你找这类工作上最麻烦的是什么？」，把回答归到最接近的一条上；
  实在归不进去才留空
- **M5 的分子 = `pain_points` 项数 ≥ 3 的行数**。所以不要合并同类项，
  「每次都要解释」和「岗位对不上」是两条，不要只记一条

### 第 3 组：平台需求（5 分钟）—— **M4 口径**

> **照读**：「你需要一个专门面向 AI Agent 开发者的求职平台吗？」
> 选项与问卷 Q8 完全一致：**非常需要 / 比较需要 / 不太需要 / 完全不需要**

记录规则 → `strong_need`（布尔）：

| 受访者回答 | `strong_need` |
|---|---|
| 非常需要 | `true` |
| 比较需要 | `false` |
| 不太需要 / 完全不需要 | `false` |

> **判定标准要固定，否则 10 份访谈之间不可比。**「比较需要」一律记 `false`——
> M4 定义的是**强需求表达**，门槛由判定阶梯的 ≥ 60% 决定，不是访谈时临场判断的。
> 若受访者答「比较需要」但同时表达了强烈不满，**记 `false`**，把强度体现在
> `pain_points` 的条数上。两个指标分开测，不要混。

### 第 4 组：差异化需求（5 分钟）—— M11 旁证

> **照读**：「你希望求职平台提供哪些现有平台没有的功能？」
> 选项与问卷 Q9 一致（8 项，其中「其他」自由文本不计入 M11 计数）。

记录规则 → `needs`（`;` 分隔，代码见下）：

| 选项 | 代码 |
|---|---|
| Agent 技能标签筛选 | `need_skill_filter` |
| Agent 岗位专区 | `need_agent_zone` |
| 技术栈匹配 | `need_stack_match` |
| 薪酬水平透明 | `need_salary_transparent` |
| 远程 Agent 岗位聚合 | `need_remote_agg` |
| 可展示 Agent 项目的作品集/主页 | `need_portfolio` |
| 只筛 Agent 相关、屏蔽无关内推与猎头消息 | `need_filter_noise` |
| 其他 | `need_other`（**自由文本须另行保留在转写里**） |

> ⚠️ **注意**：问卷 Q9 问的是「现有平台没有的功能」。现在已知竞品
> （`agenticcareers.co` / `agenticengineeringjobs.com`）已经提供了技能标签、Agent 岗位专区。
> 因此这一问要**追加一句**：「这些功能里，哪些是你在 agenticcareers 这类站点上也没找到的？」
> 追问结果记在转写里，**供任务 8 [H4.1] 判断差异化是否成立**。
> 注意：M11 的计数**不因这条追问而改变**——`needs` 仍按原口径记录，避免口径漂移。

### 第 5 组：价值认同（3 分钟）—— M12 旁证

> **照读**：「『AgentJobs 让你不用在招聘时反复解释 Agent 是什么，就能找到理解你技术栈的雇主。』
> 你对此的认同程度是？」5 分量表：非常同意 / 同意 / 一般 / 不同意 / 非常不同意

记录规则 → 访谈侧不入表（`interviews.csv` 没有 M12 字段）。
**把答案写在转写里**，供任务 8 [H4.1] 参考。M12 的主口径在问卷 Q10。

### 第 6 组：收尾（2 分钟）

- 「你认识其他在做 Agent 开发、正在找工作的朋友吗？」（**转介绍是 S1 最快的补充来源**）
- 「你愿意留邮箱，上线时通知你吗？」（与着陆页订阅打通，但**不要在这一步推销着陆页**——会污染 M1 的渠道归因）

## 早期警报（`validation-metrics.md`「何时拉响早期警报」）

> **前 5 个开发者访谈中 0 人表示强需求（M4 早期信号）→ 暂停当前触达渠道，
> 改用开发者社群直接触达。**

这条是**换渠道**，不是**改产品**，也不是**放弃**。

## 一行怎么写（照抄表头）

```
respondent_id,skill_tags,job_search_status,pain_points,needs,strong_need,interview_date,channel
```

填好的样子：

```
dev-001,LangChain;AutoGen;Python,actively_looking,pp_repeat_explain;pp_salary_opaque;pp_few_remote,need_skill_filter;need_salary_transparent;need_remote_agg,true,2026-10-28,github
```

**规则**：
- 多值字段一律用**英文分号 `;`** 分隔（中文分号 `；` 脚本不识别，会导致该行解析失败）
- `respondent_id` 用 `dev-001` 递增，**不写真实姓名**
- `strong_need` 只写 `true` / `false`
- `interview_date` 用 ISO 8601（`2026-10-28`）
- 转写文本路径**不入表**，另行归档并在备注里记路径

# 第二部分：企业深度访谈（H2.1）

**目标**：5 家（理想 8）。**时长**：30–40 分钟。

## 触达渠道

LinkedIn、AngelList/Talenta、Crunchbase、AI 公司名单、技术博客招聘公告、AI 招聘群。
**保持专业简洁，避免冷邮件轰炸。**

## 开场白（照读）

> 「您好，我们在做 AI Agent 开发者招聘方向的研究，想了解贵司在招这类人才时的实际情况。
> 约 30 分钟，不推销任何东西，也不涉及贵司的具体岗位信息。结论只会做汇总统计。可以吗？」

## 提问提纲

**这 6 个问题直接对应 `companies.csv` 的 6 个指标字段，缺一不可。**

### Q1 — 企业在做什么 Agent 项目？（`agent_projects`）

> 「贵司目前在做哪些 AI Agent 相关的项目？团队规模大概多少？」

### Q2 — 招聘上遇到什么困难？（`hiring_challenge`）

> 「招 AI Agent 开发者，目前最大的困难是什么？」

### Q3 — 要求候选人具备什么技能？（`required_skills`）

> 「这个岗位要求候选人具备哪些技能？哪些是必须、哪些是加分？」

> **追问**：「这些技能里，哪些是通用招聘渠道筛不出来的？」
> 这句话是**差异化假设的直接检验点**，答案要记进转写。

### Q4 — M6：愿不愿意使用专门平台（`interested_in_platform`）

> **照读**：「**如果有一个专门面向 AI Agent 开发者的平台，贵司是否愿意在上面发布职位/招聘？**」
> 答案：**是 / 否**（不要「可能」「看情况」——追一句「那我们先记『是』可以吗？」）

> ⚠️ **M6 与 M8 必须分开问，二者不等价，不可互相代替。**
> - **M6（本问）** = 愿不愿意**用**这个平台 → `interested_in_platform`
> - **M8（Q5）** = 承诺**现在就发布**职位 → `committed_to_post`
>
> 有人会说「会用，但暂时没岗位要发」——这在 M6 是 `true`、在 M8 是 `false`。
> 这正是要区分的原因：5 家样本下 M6/M8/M9 若高度共线，
> 判定阶梯的三道供给关卡会退化成一道。

### Q5 — M8：承不承诺发布职位（`committed_to_post`）

> **照读**：「如果平台上线，**贵司愿意在上面发布真实的 Agent 岗位**吗？」
> 答案：**是 / 否**

**答「是」时必须立刻追问下去（这直接喂给任务 5 [H2.2] 的 seeding）**：

> 「太好了，能不能现在就花两分钟，跟我一起把这个岗位的**具体内容**过一遍？
> 职位名、描述、必需的技能标签、薪资范围、工作类型——有草稿最好，没有我们边聊边记。」

产出：一份**可发布的职位内容草稿**（不是口头承诺）。
`requirements.md` 验证期验收标准第 8 项要求 M8 承诺的企业**已提供具体职位内容**，
否则平台将以空职位集上线，第一印象即失败。

> **保底目标**：2 家（对应 M8 理想值 40%），**保底 1 家**。

### Q6 — M7：招聘难度打分（`difficulty_score`）

> **照读**：「招 AI Agent 开发者，您觉得难度打几分？1 分最简单，10 分最难。」

记录规则：1–10 的数字，**小数可保留**（如 7.5）。
**这是企业自评的绝对难度**，不是「跟通用岗位比难多少」——照字面问，别加比较基准。

### Q7 — M9：有没有招聘预算（`has_budget`）

> **照读**：「贵司目前有没有针对 AI Agent 岗位的招聘预算？已批的或在计划中的都算。」

> **追问**：「预算大概是招聘平台订阅费能覆盖的量级吗？」
> 答案记进转写（供任务 11 [H5.2] 的单用户经济模型），但**不影响 `has_budget` 的取值**。

### 一行怎么写（照抄表头）

```
company_id,agent_projects,hiring_challenge,required_skills,interested_in_platform,has_budget,committed_to_post,difficulty_score,interview_date
```

填好的样子：

```
co-001,内部知识库 Agent 与客服 Agent,简历合格率低且难判断真实能力,LangChain;Python;RAG;向量数据库,true,true,true,8,2026-10-30
```

## 提交数据的两条路径

1. **直接填 CSV**：把表头 + 每场访谈一行，写进 `validation/data/companies.csv`
2. **填模板**：`validation/schemas/templates/companies.csv` 与 `interviews.csv` 已备好表头

**填完必须用脚本校验**，否则格式错误会在第 5 周打分时才暴露：

```bash
# 脚本会明确报出缺列、非法枚举值、日期格式错误等
python3 validation/compute_metrics.py --data-dir validation/data
```

> **不要**手工估算 M4–M9 —— `validation-metrics.md` 要求这些指标必须能从结构化数据直接聚合。
> 脚本读不出数据的指标会报「无数据源」，这是**预期行为**，
> 但**因为 CSV 格式错误而读不出**不是。

# 附：触达话术

> 这几段是**邀请**，不是推销。目的是把人约出来，**不是**当场把人变成订阅者。
> 着陆页的订阅归因（M1）由 `landing/PROMO.md` 的推广动作负责，
> 在访谈里塞链接会污染渠道归因数据。

### 开发者（GitHub / Discord / 社区 DM）

> 「你好！我在做一份关于 AI Agent 开发者求职的调研——不是招聘，是想搞清楚大家找工作时
> 真正卡在哪。大概 30 分钟，聊完给点小反馈（可匿名），没有推销任何东西。
> 方便的话我把时间发你？」

### Reddit / 公开社区

> **不要**在帖子正文里发链接招人。用「求教 + 招募受访者」的形式：
> 「调研招募：想找 10 位做 AI Agent 的开发者聊聊求职。我自己也在踩这个坑，
> 想搞清楚是不是只有我这样。有兴趣的私信我，时间不多。」

### 企业（LinkedIn / 邮件 / 招聘负责人）

> 「您好，我在做 AI Agent 开发者招聘方向的行业研究，想了解贵司招聘这类人才的实际
> 情况和难点。约 30 分钟，不涉及贵司具体岗位信息，不推销产品，结论只做汇总统计。
> 如果贵司近期不招聘，也想听听您的判断——同样有价值。」

> ⚠️ **「近期不招聘」的企业也要约**。他们提供的「不招聘的原因」是 M2 供给侧的关键反向信息，
> 而且他们是潜在的未来雇主（M8 的后续来源）。
